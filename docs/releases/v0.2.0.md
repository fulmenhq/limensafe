# limensafe v0.2.0 — release notes

> **Date**: 2026-07-09
> **Theme**: First public release
> **Capability arc with PR refs**: [`CHANGELOG.md`](../../CHANGELOG.md)

## In one paragraph

limensafe v0.2.0 is the first public release of the Confidential Context
Leakage (CCL) detector. If secret scanners stop credential theft and DLP
stops regulated identity from leaving the boundary, limensafe stops
**relationship disclosure** — client names, codenames, fixtures, paths,
and branch slugs that look ordinary until someone correlates them. This
cut takes the v0.1.0 MVP workflow and adds the contracts and operator
tooling real adoption needs: published JSON Schemas, runtime catalog
enforcement, catalog-building helpers, allowlists, publish-surface audit,
rewrite hygiene guidance, and scan behavior that holds up in release and
CI gates.

## Dogfooded before publication

Before this first public release, limensafe was run against its own
repository — the working tree, every ref, and the full commit history —
using its `audit-publish` and history-scan surfaces. Everything the audit
surfaced was remediated on a dedicated operator pass before the repository
went public. The detection is reproducible and mechanical; the remediation
took operator judgment. We treat that as the standard workflow, not a
one-time cleanup.

## Who this is for

| Audience                                | What v0.2.0 gives you                                                                                                                                                                 |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Security / platform architects**      | A named gap class (CCL) with a deterministic detector, two-layer catalogs (rules in-repo, vocabulary out-of-band), and a redaction-safe report your own tooling can trust             |
| **Senior DevOps / release engineering** | Exit codes and stream separation locked for CI wrappers; versioned stdout schema; bare-mirror and piped-consumer reliability; go/no-go publish-surface audit before a visibility flip |
| **CXO / engagement owners**             | A mechanical answer to “are we about to publish something that names a relationship we meant to keep confidential?” without shipping the vocabulary corpus into the open repo         |
| **Senior developers**                   | Pre-commit / PR-diff / history / full-ref scopes on one CLI; catalog authoring from a term-list; allowlists for the “public OSS tool that is also a private codename” case            |

**limensafe coexists with credential scanners and PII / DLP. It does not
replace them.** Pair it with your secret scanner in the same pre-commit
and CI gate; the classes do not overlap.

## What's new since v0.1.0

### Contracts you can build against

Scan stdout is pinned by a published, versioned JSON Schema. Emitted
documents carry `scan_metadata.output_schema_version` (**1.1.0** in this
release) so CI consumers and `jq` pipelines can branch on shape, not on
tool version. Catalogs have a published schema as well, and operator-
supplied catalogs are validated at load time against the copy embedded
in the binary — so local runs, CI, and installed binaries enforce the
same contract.

### Catalog authoring without hand-writing every entity

`limensafe catalog build` turns a flat term-list into a schema-
conformant catalog. The original `PROTECTED==>replacement` grammar
remains compatible; structured lines add regex-backed detectors and
literal or regex allowlist entries. Generated IDs are stable and
opaque. Malformed input exits as a configuration error. Diagnostics
stay structural — line numbers and reasons, never protected values.

### Allowlists when a term is confidential in one place and public in another

Catalogs can declare top-level allowlist entries. A suppression
subtracts a covered match **before** findings and co-occurrence rules
run — the common case where a codename is also a public OSS project, or
where mentioning a filename is fine but leaking its contents is not.
Suppressions are counted in scan metadata (never silent); explain output
uses alias-safe IDs only.

`catalog visibility-allowlist` can resolve repository visibility and
generate allowlist entries for names that are **currently** public. It
fails safe: lookup failures, missing credentials, rate limits, and
ambiguous responses never produce a “public” allowlist entry.

### Publish-surface audit — before the repo goes public

`scan` audits the surface you name. **`audit-publish` audits every ref
the repository would expose when made public** — not just the branch
you are looking at. It flags content-divergent refs and danger-pattern
names (`backup/*`, archive/snapshot/WIP patterns, and similar). The
report is a go/no-go: `summary.publish_safe`, `leak_vector_refs`, and a
`suggested_action` per ref, under the same redaction-safe posture as
scan.

Companion rewrite hygiene guidance states a simple rule: a
confidentiality rewrite is not complete until every artifact it created
is off the publishable remote **and** a fresh-clone publish-surface
audit is clean.

### Metadata and reliability for real gates

Core scan counters are present-with-zero instead of omitted when empty.
Skip accounting reconciles across file skips and directory prunes, so
`files_skipped`, `directories_skipped`, and `files_skipped_by_reason`
are stable for CI and `jq`. Allowlist suppressions appear as stable
metadata fields.

Tracked-tree scans accept explicit repository paths with space-separated
archive refs; bare mirror repositories work for archive scans and
attestations. Closed stdout/stderr consumers behave predictably:
advisory stderr is best-effort; broken stdout is a classified runtime
error — not a silent SIGPIPE or generic failure.

## Why this is v0.2.0

The delta from v0.1.0 is feature-bearing, not a patch. This release adds
new public commands, published schemas, catalog authoring capabilities,
output metadata, and the first public-release documentation package.
SemVer therefore moves to the next minor line. The prior `v0.1.0` tag
remains valid and is not re-cut.

## Migration notes

### Scan-output consumers

Branch on `scan_metadata.output_schema_version`. Current emission is
**1.1.0** (additive allowlist suppression fields). Common counters are
stable present integers or objects — plan for zeros, not missing keys.

### Catalog authors

Catalogs that conformed to the v1.0 catalog shape continue to validate.
Opt into top-level allowlists and structured term-list input when that
reduces manual YAML. Loader diagnostics avoid echoing protected values;
use schema paths and structural hints as the debugging surface. New
catalogs should set `$schema` to the hosted catalog schema URI (omitted
`$schema` still loads with a warning).

### Release operators

Before any public visibility flip:

1. Run `audit-publish` from a **fresh clone** (working trees can mask
   remote refs you deleted only locally).
2. Include both tracked-tree (`--git-archive`) and full-history
   (`--git-history-all`) paths in the release gate.
3. Keep private catalog content and operator findings **out of the
   repository**. Commit the proof (attestation), not the corpus.

See [`RELEASE_CHECKLIST.md`](../../RELEASE_CHECKLIST.md).
