# limensafe v0.2.1 — release notes

v0.2.1 adds explicit coverage gates and public release verification
material. It updates gofulmen to v0.3.6 and chi to v5.3.2 and removes
unconditional forwarded-client-IP rewriting. Go 1.25 is retained;
build validation requires a patched Go 1.25.13 or newer.

## Coverage gates

`scan` and `audit-publish` report selected-scope coverage. Release mode
fails closed when required coverage is incomplete, including a run with
zero findings. Explicit, reason-specific skip ceilings apply only to
budgetable gaps; fatal runtime failures are not converted into clean
results. Coverage is for the selected scope, not proof that every
possible repository surface was inspected.

The release detector threshold remains medium. Release mode does not
introduce a threshold override.

## Migration

- Select scan schema **1.2.0** using `scan_metadata.output_schema_version`;
  select publish-surface schema **1.1.0** using its top-level
  `output_schema_version`. Validators
  pinned to older schemas must update for the new coverage fields.
  Older published schemas are preserved for historical outputs.
- Check `summary.coverage` as well as finding counts. Release-mode
  incomplete coverage returns **1** even when findings are empty.
- Invalid configuration returns **2** before extraction; fatal runtime
  or I/O errors retain **3** precedence over findings or coverage gaps.
  Valid JSON remains on stdout and diagnostics remain on stderr.
- Existing local scans remain local unless release mode is explicitly
  selected. Do not treat a local exit-zero result alone as evidence of
  complete coverage; inspect the coverage summary.

## Release verification

Signed annotated tags are verified against the public GPG export,
fingerprint anchors and authorized signing subkey in their own tagged
commit, using an isolated keyring. Primary signatures and unauthorized
signing subkeys are rejected. Signature-time expiry and revocation
checks distinguish historical validity from current signing authority.

See [public verification](../security/release-pins.md) for commands,
minisign blob/ID checks and historical-key semantics. Hosted verification
is additional evidence, not a replacement for committed-pin validation.
Manifest signing and publication remain separately authorized manual
steps; the workflow creates a draft only after its tag gate passes.

v0.2.0 assets remain historical provenance candidates, not a retroactive
committed pin or a re-signing claim.
